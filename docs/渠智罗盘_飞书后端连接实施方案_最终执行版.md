# 渠智罗盘：飞书前后端连接实施方案（最终执行版）

> 版本日期：2026-08-13
>
> 适用项目：`<channel-compass目录>`
>
> 适用基线：当前11张正式CSV、现有飞书多维表格、已生成的“渠智罗盘”应用、1条AI摘要与通知自动化、3个人工处置工作流
> 核心目标：以最小改动把Python分析结果安全同步到飞书，并把人工审批与执行反馈拉回本地，完成可演示的人机协同闭环。

---

## 1. 实施结论

本阶段采用“本地Python主动同步飞书”的方案：

```text
企业脱敏模拟数据
→ Python数据审计、模型与规则分析
→ 生成11张正式结果CSV
→ OpenAPI按稳定编号增量同步
→ 飞书AI解释与通知
→ 飞书应用展示
→ 人工提交方案、审批、执行与反馈
→ OpenAPI拉回反馈
→ 下一轮Python分析读取反馈
```

本阶段不建设公网服务器，不实现飞书按钮直接调用个人电脑上的Python。同步由本地命令手动触发；电脑关闭时不会自动运行，因此不得对外表述为实时云服务。

比赛提交前的最低完成标准是：

1. Python能够只读连接飞书并发现表、字段和记录；
2. Dry Run能够准确给出新增、更新、跳过和失败数量；
3. 至少打通“渠道客户—风险事件—处置任务—模型指标”4张核心表；
4. 新红色风险进入飞书后能够生成AI摘要并通知；
5. 人工能够在应用中完成方案、审批、执行和有效性反馈；
6. Python能够拉回一条反馈，且不会覆盖飞书人工字段；
7. 同一批数据连续同步两次不产生重复记录。

11张表和8组关联是完整目标，但不作为核心闭环首次联调的前置条件。

## 2. 系统职责与边界

| 组件 | 负责内容 | 禁止内容 |
|---|---|---|
| Python后端 | 数据校验、模型预测、规则判断、健康评分、What-if测算、生成事件和任务底稿 | 自动审批、自动停发、自动调额、替代人工业务判断 |
| 飞书多维表格 | 保存结果、关联、人员、审批、执行和反馈 | 重复创建Python已经生成的正式任务 |
| 飞书AI | 根据结构化证据生成摘要与人工核查建议 | 重算模型概率、虚构事实、自动做授信或法务决定 |
| 飞书应用模式 | 展示风险、证据、情景、任务和审批界面 | 作为模型计算引擎 |
| 业务人员 | 填写人工方案、审批、执行、确认预警有效性 | 用演示值冒充真实处置结果 |

数据口径继续保持：

- 数据为企业提供的脱敏模拟数据；
- 当前动态到期运行模式为`historical_replay`；
- 当前模型用于订单出库后120天内超期风险排序，不解释为精确坏账概率；
- “风险加权应收暴露”不是预期坏账损失；
- What-if是参数化情景测算，不证明干预具有因果效果；
- 库存风险是SKU—仓库口径，客户商品表仅表示采购暴露，不表示客户实际持有库存。

## 7. 字段所有权

### 7.1 风险事件

Python允许更新：

- 客户编号、客户名称；
- 风险类型、风险等级、触发时间、数据快照；
- 关键指标、风险金额、风险加权应收暴露；

- 客户历史摘要、规则解释、建议动作；
- 模型版本、模型阈值、data_source；
- 业务类型、动态到期阶段、客户履约等级；
- 动态建议动作、处置强度、规则版本。

Python禁止覆盖：

- AI风险摘要；
- 处理状态；
- 通知状态、通知时间；
- 关联客户、处置任务、订单证据、风险处置时间线；
- 按钮、公式和查找引用字段。

新建事件初始化：

- `AI风险摘要`留空；
- `处理状态=待处理`；
- `通知状态=未发送`；
- `通知时间`留空。

### 7.2 处置任务

Python允许更新：

- 风险事件编号、客户编号、客户名称；
- `AI建议动作`；
- 创建时间、截止日期、data_source；
- 风险类型、风险等级、风险分、影响金额；
- 关键证据、置信说明；

- 处置强度、审批建议、建议负责人角色、SLA状态。

`AI建议动作`虽然字段名包含AI，但其内容来自Python规则和模型结果，不再配置第二条飞书AI自动化生成它。

Python禁止覆盖：

- 人工处置方案；
- 负责人、审批人；
- 审批状态、审批意见、审批结论和审批时间；
- 执行状态、完成时间、实际回款金额、执行结果；
- 预警有效性、反馈备注；
- 关联风险事件、风险处置时间线；
- 三个按钮字段。

新建任务初始化：

- `人工处置方案=待填写`；
- `审批状态=待审批`；
- `执行状态=待处理`；
- `预警有效性=待确认`；

如果飞书实际没有“审批时间”或“审批结论”字段，程序不得虚构或写入。字段白名单以API发现结果为准。

### 7.3 处置情景

- Python可更新全部测算字段；
- `人工决策`属于人工字段，已有记录不得覆盖；
- 关联客户由关联阶段单独写入。

### 7.4 其余表

- 普通业务字段按明确白名单更新；
- 关联字段在关联阶段单独处理；
- 人员、按钮、公式、查找引用和反向关联字段全部跳过；
- 空值默认不覆盖飞书已有非空值；
- 不删除飞书中本轮本地数据不存在的记录。

## 8. API客户端要求

`src/feishu_client.py`只负责通用API通信：

1. 获取并缓存`tenant_access_token`；
2. 列出数据表；
3. 列出字段；
4. 分页查询记录；
5. 批量新增记录；
6. 批量更新记录；
7. 统一错误处理和脱敏日志。

令牌接口：

```http
POST https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal
```

记录查询：

```http
POST /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records/search?page_size=500
```

必须循环处理`page_token`，直到`has_more=false`。

批量写入：

```http
POST /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records/batch_create
POST /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records/batch_update
```

实施时每批100条、各表串行执行，同一张表不并发写。每次请求同时检查：

- HTTP状态码；
- 响应体`code`是否为0；
- 返回记录数量是否符合请求数量；
- 失败响应中的`X-Tt-Logid`。

仅对限流、写冲突、超时和临时服务错误执行`1、2、4、8`秒退避，最多4次。权限错误、字段错误、重复稳定键、无效`table_id`或`app_token`不得自动重试。

日志不得输出`APP_SECRET`、完整token或完整`APP_TOKEN`。

写入前根据飞书字段类型转换：

| 类型 | 写入规则 |
|---|---|
| 文本 | 字符串；更新时空值默认不发送 |

## 10. 稳定编号Upsert

每张表固定执行：

```text
1. 读取本地CSV并校验稳定更新键
2. 分页读取飞书记录
3. 建立stable_id -> record_id映射
4. 本地有、飞书无：加入新增集合
5. 本地有、飞书有：仅比较Python可写白名单
6. 值相同：跳过
7. 值变化：加入更新集合
8. Dry Run只输出计划
9. --apply时分批新增和更新
10. 重读新增记录并补齐stable_id -> record_id映射
11. 输出新增、更新、跳过、失败数量
```

安全约束：

- 不以客户名称或行号作为更新键；
- 不清空整张表后重导；
- 不删除本轮本地不存在的远端记录；
- 不用空值清除已有非空值；
- 正式写入必须同时满足`.env`允许写入和命令显式传入`--apply`；
- 连续运行相同数据时，第二次应全部或绝大多数为`skipped`。

## 13. 与飞书自动化和工作流衔接

长期保留1条“AI风险摘要＋高风险通知”自动化：

```text
触发表：风险事件
风险等级 = 红色
处理状态 = 待处理
AI风险摘要 = 空
通知状态 = 未发送
```

执行：

1. 根据当前结构化字段生成AI风险摘要；
2. 回写AI风险摘要；
3. 查询对应处置任务；
4. 向负责人或团队群发送消息；
5. 成功后更新通知状态和通知时间。

Python不得清空AI风险摘要，也不得把通知状态重新改为“未发送”。

三个工作流分工：

| 工作流 | 触发按钮 | 完成内容 |
|---|---|---|
| 工作流1 | 提交处置方案 | 校验方案、负责人、审批人，提交待审批状态 |
| 工作流2 | 确认审批结果 | 记录批准或驳回、审批意见，控制是否进入执行 |
| 工作流3 | 提交处置结果 | 校验执行结果和预警有效性，完成任务并更新事件 |

API同步不得写入三个按钮、审批结果或执行结果。
