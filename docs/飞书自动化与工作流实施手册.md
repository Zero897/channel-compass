# 渠智罗盘：飞书自动化与工作流实施手册（精简版）

## 1. 实施目标

本手册用于在飞书多维表格中完成“渠智罗盘”的最小可演示闭环：

```text
Python生成风险结果和处置任务
→ 飞书自动建立表间关联
→ 飞书AI生成风险摘要并发送预警
→ 人工制定方案并审批
→ 人工执行并提交结果
→ 处置结果回写风险事件
```

本版只保留：

- 8条表间关联自动化；
- 1条“AI风险摘要＋高风险通知”自动化；
- 1个处置审批工作流；
- 1个任务完成工作流。

暂不搭建负责人自动分派、SLA定时提醒、每日经营摘要、数据新鲜度提醒和What-if选择工作流。这些功能不影响入围赛核心闭环，可以通过人员字段、公式、筛选视图和人工操作展示。

## 2. 系统边界

1. Python负责数据审计、特征计算、模型训练、风险评分、正式风险事件和正式处置任务生成。
2. 飞书负责跨表关联、AI解释、通知、人工审批、执行记录和状态回写。
3. Python是正式处置任务的唯一创建者，飞书不得创建第二条处置任务。
4. AI不得自动批准方案，不得直接调整授信、停止发货或进入法务流程。
5. 人工处置方案、审批结果、执行结果和预警有效性必须由人员确认。
6. 当前数据运行模式为 `historical_replay`，答辩界面必须标明“历史回放”。

## 3. 配置前检查

### 3.1 正式表与主字段

| 表 | 主字段 |
|---|---|
| 企业渠道客户 | 客户主键 |
| 企业风险事件 | 事件编号 |
| 企业处置任务 | 任务编号 |
| 企业订单证据 | 订单证据编号 |
| 企业处置情景 | 方案编号 |
| 企业风险处置时间线 | 过程事件编号 |
| 企业库存风险汇总 | 库存汇总编号 |
| 企业库存风险 | 库存对象编号 |
| 企业模型指标 | 指标编号 |
| 企业动态回款监控 | 动态监控编号 |
| 企业客户商品风险暴露 | 采购暴露编号 |

所有客户编号、事件编号、任务编号、订单号和物料编码均使用“单行文本”，不能改为数字、日期、公式或自动编号。

不要把 `legacy_demo` 或 `demo_output` 中的演示数据导入正式任务表。

### 3.2 新增飞书字段

#### 企业风险事件

- `关联客户`：双向关联到企业渠道客户，不允许关联多条目标记录；
- `通知状态`：单选，未发送、已发送、发送失败；
- `通知时间`：日期时间。

#### 企业处置任务

- `关联风险事件`：双向关联到企业风险事件，不允许关联多条目标记录；
- `负责人`：人员字段，由团队人工选择；
- `审批人`：人员字段；
- `审批意见`：多行文本；
- `审批时间`：日期时间；
- `提交审批`：按钮，可选；
- `提交完成`：按钮，可选。

#### 其他子表

- 企业订单证据：`关联风险事件`；
- 企业处置情景：`关联客户`；
- 企业风险处置时间线：`关联风险事件`、`关联处置任务`；
- 企业动态回款监控：`关联客户`；
- 企业客户商品风险暴露：`关联客户`。

所有关联字段的“关联数据范围”选择“所有记录”，关闭“允许关联多条目标记录”。

## 4. “AI建议动作”是否需要自动化

不需要。

企业处置任务中的`AI建议动作`在Python生成正式CSV时已经写入，因此刚导入飞书就有内容。当前链路是：

```text
Python识别风险类型
→ 风险事件生成规则化建议动作
→ 红色风险生成处置任务
→ 风险事件.建议动作写入处置任务.AI建议动作
```

目前该字段实际是Python规则模板，不是飞书AI现场生成。为了避免误解，推荐在飞书中把显示名称改为`系统建议动作`；如果暂时不改名，应在字段说明中注明“由Python规则生成”。

该字段与另外两个字段不同：

| 字段 | 来源 | 用途 |
|---|---|---|
| AI建议动作（推荐改名为系统建议动作） | Python规则模板 | 提供核查和处置方向 |
| AI风险摘要 | 飞书AI自动化 | 根据结构化证据生成简短解释 |
| 人工处置方案 | 负责人填写 | 实际提交审批和执行的方案 |

不要再创建一条飞书自动化覆盖`AI建议动作`，否则会出现以下问题：

- Python与飞书存在两个生成来源；
- 重导数据后字段内容可能互相覆盖；
- 无法判断建议来自业务规则还是大模型；
- 增加自动化数量，却没有增加核心演示价值。

## 5. 自动化A1—A8：八类关联回填

### 5.1 通用配置步骤

每个子表单独建立一条自动化。八条自动化虽然逻辑相同，但目标表和字段不同，分开配置更容易排错。

1. 打开多维表格，点击右上角“自动化”。
2. 选择“创建自定义流程”。
3. 触发器选择“新增/修改的记录满足条件时”。
4. 触发表选择当前子表。
5. 设置触发条件：外部键不为空，并且关联字段为空。
6. 添加“查找记录”动作。
7. 选择目标主表。
8. 查找条件设为目标表文本键精确等于当前记录的外部键。
9. 添加“更新记录”动作。
10. 更新对象选择“触发流程的当前记录”。
11. 将查找到的目标记录写入当前记录的关联字段。
12. 保存、启用并用一条记录测试。

如果账号支持条件分支或查找数量判断：

- 找到1条：正常回填；
- 找到0条：不新建目标记录，只通知关联失败；
- 找到多条：停止回填并通知目标键重复。

如果账号不能判断查找数量，则建立两个检查视图：

- 主表“编号重复检查”；
- 子表“外部键不为空且关联字段为空”。

### 5.2 八条关联映射

| 自动化 | 触发表 | 外部键 | 查找目标表 | 目标键 | 回填字段 |
|---|---|---|---|---|---|
| A1 | 企业风险事件 | 客户编号 | 企业渠道客户 | 客户编号 | 关联客户 |
| A2 | 企业处置任务 | 风险事件编号 | 企业风险事件 | 事件编号 | 关联风险事件 |
| A3 | 企业订单证据 | 风险事件编号 | 企业风险事件 | 事件编号 | 关联风险事件 |
| A4 | 企业处置情景 | 客户编号 | 企业渠道客户 | 客户编号 | 关联客户 |
| A5 | 企业风险处置时间线 | 风险事件编号 | 企业风险事件 | 事件编号 | 关联风险事件 |
| A6 | 企业风险处置时间线 | 关联任务编号 | 企业处置任务 | 任务编号 | 关联处置任务 |
| A7 | 企业动态回款监控 | 客户编号 | 企业渠道客户 | 客户编号 | 关联客户 |
| A8 | 企业客户商品风险暴露 | 客户编号 | 企业渠道客户 | 客户编号 | 关联客户 |

A2已经完成“处置任务关联风险事件”，不需要再额外建立同功能的自动化。

### 5.3 可交给飞书AI的通用提示词

每次只让飞书AI建立一条工作流或自动化，并替换方括号中的内容：

```text
请创建一个关联字段自动回填流程。

触发表：[触发表]
触发条件：记录新增或[外部键]发生变化；[外部键]不为空；[回填字段]为空。

执行步骤：
1. 在[查找目标表]中查找记录；
2. 查找条件为[目标键]精确等于当前记录的[外部键]；
3. 找到唯一一条记录时，更新触发流程的当前记录；
4. 将查找到的目标记录写入当前记录的[回填字段]；
5. 找不到或找到多条记录时，不新建记录、不随意选择，只发送异常提醒。

禁止创建客户、风险事件或处置任务。
```

### 5.4 关联验收

1. 每条自动化至少测试一条正常记录。
2. 修改非关联字段时不得重复增加关联。
3. 所有“关联异常”视图最终应为0条。
4. 不允许按客户名称、日期或行号匹配。
5. 不建立库存风险与客户的直接关联。

## 6. 自动化B：AI风险摘要与高风险通知（合并）

原来的“AI风险摘要”和“高风险通知”合并为一条自动化，减少一次额外触发。

### 6.1 触发器

- 触发表：企业风险事件；
- 触发：记录新增，或者风险类型、风险等级、关键指标、风险金额、客户历史摘要、规则解释发生变化。

### 6.2 触发条件

- 风险等级等于红色；
- 处理状态等于待处理；
- AI风险摘要为空；
- 通知状态不等于已发送。

### 6.3 执行步骤

1. 添加“AI生成文本”节点。
2. 使用字段选择器插入客户名称、风险类型、风险等级、关键指标、风险金额、客户历史摘要和规则解释。
3. 将AI结果写回当前风险事件的`AI风险摘要`。
4. 按当前风险事件的`事件编号`，在企业处置任务中查找对应任务。
5. 如果任务负责人不为空，向负责人发送高风险消息。
6. 如果负责人为空，向比赛团队群发送消息并标注“待人工分派”。
7. 发送成功后更新当前风险事件：通知状态为已发送，通知时间为当前时间。
8. 发送失败时更新通知状态为发送失败。

如果飞书在同一流程中无法引用刚刚写回的`AI风险摘要`，消息中的摘要应直接引用AI节点输出，而不是重新读取字段。

### 6.4 AI提示词

```text
你是ICT渠道经营风险分析助手。仅依据下列当前记录生成风险摘要，不得补充不存在的事实。

客户：[插入 客户名称]
风险类型：[插入 风险类型]
风险等级：[插入 风险等级]
关键指标：[插入 关键指标]
风险金额：[插入 风险金额]
客户历史摘要：[插入 客户历史摘要]
规则解释：[插入 规则解释]
系统建议动作：[插入 AI建议动作或风险事件中的建议动作；没有该字段时省略]

请在120字以内输出：
1. 风险结论；
2. 两项最关键证据；
3. 下一步人工核查动作；
4. 证据不足时明确写“需人工复核”。

不要决定信用额度、停止发货或进入法务流程；不要宣称客户一定违约；不要把模型概率解释为精确违约率。
```

如果企业风险事件表没有`AI建议动作`，不要为了提示词新增该字段，直接使用现有的`建议动作`，或者删除“系统建议动作”这一行。

### 6.5 消息模板

```text
【渠智罗盘高风险预警】
客户：[插入 客户名称]
风险：[插入 风险类型] / [插入 风险等级]
影响金额：[插入 风险金额]
证据：[插入 关键指标]
AI摘要：[插入 AI节点输出]
任务编号：[插入 查找到的任务编号]
请在 [插入 查找到的截止日期] 前完成人工复核并更新任务状态。
```

所有变量必须通过字段选择器插入，不能手工输入双花括号变量。

### 6.6 自动化B验收

- AI摘要不出现未替换变量；
- AI不补充记录外事实；
- AI不直接作出授信、停发或法务决定；
- 消息只发送一次；
- 通知状态和通知时间正确回写；
- 负责人为空时消息能进入团队群；
- 自动化不会创建新的处置任务。

## 7. 工作流一：人工处置方案审批

### 7.1 推荐方案

如果账号支持正式“审批”或“人工任务”节点，使用一个工作流完成提交、审批和结果分支。如果不支持，则使用按钮、审批状态和消息通知模拟审批，但审批结果仍由人员手工选择。

### 7.2 正式审批节点配置

1. 在企业处置任务表增加`提交审批`按钮。
2. 新建工作流，触发器选择点击`提交审批`。
3. 进入条件：
   - 人工处置方案不为空且不等于待填写；
   - 负责人不为空；
   - 审批人不为空；
   - 审批状态等于待审批或已驳回；
   - 执行状态为待处理或处理中。
4. 条件不满足：不改变状态，向负责人发送缺失字段提示。
5. 条件满足：进入人工审批节点。
6. 审批消息展示任务编号、客户、风险类型、影响金额、系统建议动作、人工处置方案和关键证据。
7. 审批通过分支：
   - 审批状态更新为已批准；
   - 执行状态更新为待处理；
   - 审批时间更新为当前时间；
   - 通知负责人开始执行。
8. 审批驳回分支：
   - 要求审批人填写审批意见；
   - 审批状态更新为已驳回；
   - 执行状态保持待处理；
   - 通知负责人修改方案后重新提交。

### 7.3 没有审批节点时

1. 负责人填写人工处置方案并点击`提交审批`。
2. 工作流校验字段后通知审批人。
3. 审批人查看记录，手工选择审批状态为已批准或已驳回。
4. 驳回时必须填写审批意见。
5. 工作流根据审批状态变化通知负责人。
6. 不允许工作流在没有人工操作的情况下自动写入已批准。

### 7.4 审批验收

- 未填写人工处置方案时不能提交；
- 提交审批不等于自动批准；
- 驳回必须有审批意见；
- 修改方案后可以重新提交；
- 未批准任务不能提交完成。

## 8. 工作流二：执行完成、反馈校验与事件回写

原来的“完成校验”和“风险事件状态回写”合并为一个工作流，不再单独建立完成回写自动化。

### 8.1 触发方式

1. 在企业处置任务表增加`提交完成`按钮。
2. 新建工作流，触发器选择点击`提交完成`。
3. 不建议让人员直接手工把执行状态改为已完成，否则可能绕过校验。

### 8.2 完成条件

依次检查：

1. 审批状态等于已批准；
2. 人工处置方案不为空且不等于待填写；
3. 负责人不为空；
4. 执行结果不为空；
5. 预警有效性为有效、部分有效或误报；
6. 实际回款金额为空时，反馈备注说明尚未核实、尚未发生或不适用；
7. 关联风险事件不为空。

### 8.3 校验不通过分支

1. 不更新执行状态；
2. 向负责人发送缺失字段提示；
3. 任务保持待处理或处理中。

### 8.4 校验通过分支

1. 当前任务的执行状态更新为已完成；
2. 完成时间更新为当前时间；
3. SLA状态更新为已完成；
4. 更新`关联风险事件`的处理状态为已完成；
5. 向负责人和团队群发送完成消息；
6. 提醒数据负责人后续导出处置反馈。

### 8.5 反馈回流

1. 从飞书导出企业处置任务。
2. 按任务编号整理为 `data/feedback/task_feedback.csv`。
3. 下次运行Python企业主链时合并人工反馈并重建时间线。
4. 飞书不新建正式风险处置时间线记录，避免Python重跑后产生重复。

### 8.6 禁止动作

- 不允许AI自动选择预警有效性；
- 不允许把空的实际回款金额自动填成0；
- 不把What-if测算结果当作真实收益；
- 不自动调整授信、停止发货或进入法务流程。

## 9. 删除或暂不搭建的功能

| 原功能 | 处理方式 | 理由 |
|---|---|---|
| 处置任务关联风险事件C1 | 删除 | 与A2完全重复 |
| 负责人自动分派C2 | 暂不搭建 | 两人团队人工选择更简单，也更适合演示人工责任 |
| 独立高风险通知D | 合并到自动化B | AI摘要生成后可直接发送通知 |
| SLA定时提醒F | 暂不搭建 | 使用SLA状态公式、即将到期视图和已超期视图即可 |
| 完成状态回写G2 | 合并到工作流二 | 完成校验通过后直接更新关联事件 |
| 数据新鲜度提醒H | 暂不搭建 | 当前是历史回放，不是实时运行 |
| 每日经营摘要I | 暂不搭建 | 仪表盘和风险视图已经满足入围赛展示 |
| What-if选择工作流 | 暂不搭建 | 人工选择字段即可展示三种方案比较 |
| AI建议动作自动化 | 不搭建 | 该字段已由Python生成，避免双来源覆盖 |

### 9.1 SLA的无自动化替代方案

保留Python生成的`SLA状态`，并建立两个视图：

- 即将到期：执行状态不是已完成，SLA状态等于即将到期；
- 已超期：执行状态不是已完成，SLA状态等于已超期。

答辩时展示视图即可，无需为了提醒再增加定时自动化。

### 9.2 What-if的无工作流替代方案
