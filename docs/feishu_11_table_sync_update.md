# 飞书十一表同步更新记录

## 实施结果

`config/feishu_sync.json`已从4张核心表扩展为11张业务结果表：

1. 渠道客户；
2. 风险事件；
3. 处置任务；
4. 订单证据；
5. 处置情景；
6. 风险处置时间线；
7. 动态回款监控；
8. 客户商品风险暴露；
9. 库存风险；
10. 库存风险汇总；
11. 模型指标。

运行控制是独立技术表，继续由`RunManager`和`FeishuRunControlStore`回写，不进入普通业务表同步。

## 写入边界

- 所有表按稳定编号执行增量upsert，不删除本地不存在的远端记录。
- 空白本地值不覆盖飞书已有非空值。
- 风险事件的AI摘要、通知和处理状态保持保护。
- 处置任务的人工方案、人员、审批、执行、反馈及按钮字段保持保护。
- 处置情景的`人工决策`保持保护。
- 所有关联字段保持保护，由飞书关联自动化维护。
- 公式、按钮、人员和反向关联类型不能进入普通同步白名单。

## 飞书端验收

1. 保持Python后端和公网隧道在线。
2. 在飞书应用点击一次“运行分析”。
3. HTTP自动化应返回202。
4. 运行控制新增一条记录，并依次显示运行中、成功。
5. 运行完成后核对11张业务表均出现在同步报告中。
6. 检查处置任务人工字段、风险事件AI摘要和既有关联字段没有被覆盖。

仍然只需要一条“运行分析→POST /api/runs”自动化，不需要为11张表分别创建自动化。
