# 飞书前端触发后端运行手册

## 1. 已实现范围

当前后端已经具备三项能力：

1. `POST /api/runs`异步接收运行请求并立即返回运行编号；
2. 将待运行、运行中、当前阶段、成功或失败回写飞书“运行控制”表；
3. 使用`models/primary_payment_risk.joblib`完成冻结模型推理，不重新训练模型，然后按稳定键增量同步11张业务结果表。

后端同时提供：

- `GET /api/health`：服务健康检查；
- `GET /api/runs/{run_id}`：查询当前进程内的任务状态；
- 单任务防重入：已有任务运行时，新请求返回HTTP 409；
- Bearer Token鉴权；
- 独立写入安全开关，默认禁止写飞书。

## 2. 飞书运行控制表

在当前多维表格中新建数据表`运行控制`，字段名称必须完全一致：

| 字段 | 类型 | 说明 |
|---|---|---|
| 运行编号 | 单行文本，主字段 | 后端生成的唯一编号 |
| 触发人 | 单行文本 | 前端传入的展示名称 |
| 触发时间 | 日期 | 接口收到请求的时间 |
| 运行状态 | 单选 | 待运行、运行中、成功、失败 |
| 当前阶段 | 单行文本 | 当前处理步骤 |
| 新增记录数 | 数字 | 本次飞书新增数 |
| 更新记录数 | 数字 | 本次飞书更新数 |
| 同步报告 | 单行文本 | 本地同步报告相对路径 |
| 错误信息 | 多行文本 | 失败原因，成功时为空 |
| 完成时间 | 日期 | 后台任务结束时间 |
| 运行分析 | 按钮 | 用于触发飞书自动化，不由Python写入 |

`触发人`当前使用文本字段，不要创建成人员字段，否则Python字符串无法直接写入。

## 3. 安装后端依赖

```powershell
& ".\.venv\Scripts\python.exe" -m pip install -r "requirements-all.txt"
```

## 4. 本地环境变量

先生成随机触发密钥：

```powershell
& ".\.venv\Scripts\python.exe" -c "import secrets; print(secrets.token_urlsafe(32))"
```

将结果写入本地`.env`，不要提交Git：

```dotenv
BACKEND_TRIGGER_TOKEN=替换为随机生成的长密钥
BACKEND_ALLOW_FEISHU_WRITE=false
BACKEND_HOST=127.0.0.1
BACKEND_PORT=8000
```

`FEISHU_APP_ID`、`FEISHU_APP_SECRET`和`FEISHU_APP_TOKEN`沿用现有配置。

## 5. 安全启动与检查

保持`BACKEND_ALLOW_FEISHU_WRITE=false`，启动服务：

```powershell
& ".\.venv\Scripts\python.exe" "src\backend_api.py"
```

另开一个PowerShell窗口检查：

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/api/health"
```

预期返回：

```json
{"status":"ok","write_enabled":false}
```

此时即使误调用运行接口，也只会返回HTTP 503，不会写飞书。

## 6. 飞书自动化HTTP节点

飞书“运行分析”按钮对应的自动化设置为：

1. 触发器：点击按钮时；
2. 执行动作：发送HTTP请求；
3. 方法：`POST`；
4. URL：`https://后续配置的公网地址/api/runs`；
5. 请求头：

```text
Authorization    Bearer 与BACKEND_TRIGGER_TOKEN相同的值
Content-Type     application/json
```

请求头名称和值分别填入飞书的“键”和“值”，不要输入引号、中文冒号或尾随冒号。请求体选择Raw JSON时，如飞书自动补充`Content-Type`，只保留`Authorization`即可。

6. 请求体：

```json
{
  "requested_by": "飞书前端",
  "control_record_id": ""
}
```

如果飞书字段选择器能取得当前记录ID，将`control_record_id`插入当前记录ID，后端会更新按钮所在记录。若暂时取不到记录ID，保持空字符串，后端会新建一条运行记录。

接口收到请求后立即返回HTTP 202，耗时约两分钟的分析在后台继续执行，飞书不需要等待HTTP连接直到计算完成。

## 7. 开启真实回写

完成运行控制表和接口联调后，停止服务，将`.env`修改为：

```dotenv
BACKEND_ALLOW_FEISHU_WRITE=true
```

重新启动服务，前端按钮才会真正执行：

```text
拉取人工反馈
→ 重建企业特征
→ 加载冻结模型推理
→ 生成风险、任务、健康度和情景结果
→ 增量同步飞书11张业务结果表
→ 回写运行控制状态
```

普通前端运行不会调用训练函数。模型重训仍使用独立训练命令，由管理员人工执行。

## 8. 公网隧道

后端健康检查通过后，另开PowerShell窗口执行：

```powershell
cloudflared tunnel --url http://127.0.0.1:8000
```

将生成的`https://随机子域.trycloudflare.com`与`/api/runs`直接拼接，中间不能有空格。Quick Tunnel只用于比赛演示，关闭进程或重新启动后地址可能变化。

## 9. 当前边界

- 当前使用临时Quick Tunnel提供公网HTTPS地址，不承诺固定域名或持续在线；
- Python后端关闭或笔记本断网时，飞书无法触发运行；
- 进程重启后，`GET /api/runs/{run_id}`不保留内存状态，但飞书运行控制表仍保留历史记录；
- 当前自动同步配置覆盖全部11张业务结果表；运行控制表由任务管理器单独回写；
- 飞书人工字段仍受原白名单保护，不会被后端覆盖。
