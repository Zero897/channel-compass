# 初始方案验收报告复核与采用结论

## 总结

《渠智罗盘_初始方案逐项验收与整改方案_20260812.docx》的核心差距分析总体合理：当前版本确实没有完整实现固定30天预测、客户—SKU需求预测、企业主链五维健康度和真实业务反馈闭环。报告正确区分了“技术接口存在”和“业务结果已经发生”。

报告中有一项事实已经过期：其记录的scikit-learn环境错误已在上一轮修复。整改前完整仓库为40/40测试通过；本轮新增功能和测试后应以最新验证结果为准。

## 直接采用

- 在企业主链输出五个健康度分项、综合分、版本和下钻证据。
- 以客户采购高库存风险商品的暴露替代不存在的“客户库存”。
- 把任务所需的风险、证据、金额、置信说明、动态阶段和审批建议带入同一任务详情。
- 输出Top20%风险金额捕获率和业务口径误报率。
- 将客户主键和指标编号置于CSV第一列。
- 保留演示反馈与真实反馈的边界，真实反馈为0时不宣称闭环率。

## 调整后采用

- 不将固定30天模型作为当前P0。根据企业反馈，采用“120天模型负责未到期订单排序＋到期日规则负责历史回放或通过时效门禁后的业务阶段判断”的双层结构。
- 4—8周库存需求先使用最近90天日均销量基线，并输出回测代理和明确边界；Croston、ETS或LightGBM待进入下一轮且有足够周序列时再比较。
- “客户—SKU预测”调整为“客户采购暴露到高库存风险SKU”；不能把采购关系解释为客户持有库存。
- 一个品牌、两个区域作为可配置展示试点，不裁剪主模型训练全集，避免在入围赛阶段因样本骤减重新训练出不稳定模型。

## 当前不采用

- 不为字面满足承诺而虚构发票、付款对象或实时ERP接口。
- 不使用当前静态授信表构造历史额度利用率，避免时间穿越。
- 不用1—2条演示反馈自动校准阈值或重训模型。
- 不宣称完成4—6周影子运行、真实飞书审批或真实人工耗时对照。

## 企业反馈的原型化落地

- 区分常规消费品分销和企业级项目类；项目类保留监控但不进入统一回款模型。
- 按到期前5天、超期1—30天、31—60天、61—120天、120天以上分层。
- 履约较差客户的超期动作升级为停止发货审批建议。
- 停发、授信和法务措施全部要求人工审批，系统不自动执行。
